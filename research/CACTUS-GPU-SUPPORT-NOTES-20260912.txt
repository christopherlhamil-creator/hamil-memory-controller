does mmap work on vram?Yes, mmap works on VRAM, but it depends heavily on how you are trying to use it and the direction of the mapping.Because mmap is a fundamental POSIX system call that maps physical page frames to virtual memory addresses, the Linux kernel handles VRAM by treating the GPU as a character device or mapping its hardware registers via a PCI driver. [1] (https://www.youtube.com/watch?v=cIUvsfutz-U&t=343), [2] (https://www.youtube.com/watch?v=1BRGU_AS25c&t=142)The two main directions of mapping work as follows:1. Mapping Physical VRAM into CPU User-Space (CPU accessing VRAM)You can directly map physical VRAM addresses into a CPU process's address space.How it works: A kernel-space driver exposes the GPU's PCI BAR (Base Address Register) using the kernel's io_remap_pfn_range or remap_pfn_range functions.The Reality: Historically, you could do this by manually mmaping the system memory file /dev/mem if you knew the hardware addresses. In modern systems, proprietary drivers like NVIDIA's handle this internally. However, you rarely write raw mmap calls for VRAM in standard code because graphic APIs (like Vulkan, OpenGL, or DirectX) manage memory virtualization automatically under the hood. Direct CPU read/writes over PCIe or NVLink to VRAM are also highly subject to massive latency penalties compared to native GPU execution.
